## 已知（B）

* 链路：PCAN 驱动 → USB2CAN（拨到 120R 终端）→ 2P 接口/双绞线 → 底座 → 各关节驱动板；夹爪控制盒挂在 4P 扩展口上（tid=1932、1997）。
* 驱动板参数：`ID_Addr` = 关节序号（1–6），`P_Serial = CAN1_MAP`（tid=1953）。→ 关节的总线地址与序号相关，但**帧 ID 如何由 `ID_Addr` 生成未知**。
* 底座 CAN 线断开会导致其后所有关节通信失败；可拔掉底座与大臂之间 4P 口分段排查。

| 步骤 | 操作 | 记录 |
|---|---|---|
| 0 | 记录固件版本（V5.1.5D?）、上位机版本、线缆与终端 | 元数据 |

## CAN 基础（与本项目相关的部分）

* **仲裁**：ID 数值越小优先级越高，位级非破坏性仲裁（显性 0 覆盖隐性 1）。若急停命令 ID 较大，在高负载下会被低 ID 帧延后——这是“软件急停不等于硬件急停”的总线层面原因之一。
* **错误状态**：Error Active → Error Passive（TEC/REC > 127）→ Bus Off（TEC > 255）。终端电阻缺失、线序错误常导致错误帧暴增甚至 Bus Off，上位机表现为大面积 `None`。
* **终端**：总线两端各 120 Ω；USB2CAN 的 120R 档提供一端，另一端在末端驱动器（D：未确认末端是否内置）。

## 与软件层的关系

`get_motor_angles` 中出现 `None` → 本项目将样本标记为无效、计入失败、禁止运动；连续失败达到阈值 → FAULT。CAN 抓包结果出来后，可以把“哪个关节通信中断”与 `None` 位置对上，作为故障诊断信息写入 `/diagnostics`。
